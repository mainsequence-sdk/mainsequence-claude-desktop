An agent icon changed in Command Center now reaches an open pane on its own. Until 0.4.19 the
pane fetched an agent's idle icon when it listed agents and kept it for five minutes in the
session's memory, and nothing re-listed while the Agents section stayed open, so a new icon
appeared only after Refresh or a new Code session.

What changes for a session:

- **Every listing re-checks.** Environment selection, paging and Refresh re-check the listed
  agents' idle icons regardless of age.
- **The Agents section re-checks once a minute.** While the pane is open on Agents, the hook
  re-checks the listed agents' idle icons every minute; the timer stops when the pane closes or
  another section is shown, and a section left open pauses after four hours until Refresh.
- **A re-check is conditional.** The worker sends the backend the entity tag (`ETag`) the hook
  holds for each drawn icon as `If-None-Match`, on the canonical icon route only. An icon the
  backend answers with 304, or with 200 and the same tag (the route sends tags but does not yet
  answer conditional requests, so the worker compares them itself), keeps its image without being
  decoded again; a changed one arrives with its new tag and is redrawn; a failed re-check keeps
  the drawn icon. Tags stay in session memory with the images.
- **Poses are unchanged.** Details and Talk still read an agent's poses when opened.

Validation: 99 Node tests (new: the worker's conditional request and its 304, 200 and refused
shapes; the hook's one-minute re-check with the held tag, redraw on change, retained icon on
failure, timer lifecycle across sections and pane close, Refresh and Details), the native Desktop
simulator tests, loader validation, distribution checks and a live check against the local
backend recorded in the verification doc. Bundles devtools 0.3.12. Update from the MainSequence
marketplace and reload the plugin in the Code chat. Node 22+ required.
