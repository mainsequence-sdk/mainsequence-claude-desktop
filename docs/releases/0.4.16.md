Deployments come to the pane. A local repository's Code detail gains a **Deploys** card
with the latest workflow run or deployment of its checked-out branch: state colour,
repository · branch · commit, start and duration, and a progress rail of step glyphs in
plan order. **Open run** shows the run with an SVG step timeline on the run's clock, step
rows with state and duration, the selected step's record and its logs with millisecond
timestamps, paged by the platform's cursor; a workflow run opens its first failed step,
else its deploy step. **All deployments** (from the card and from Home) lists the
environment's entries newest first with Load more, and Home's This session card shows
the session branch's latest run with View. A run shown while pending, queued or running
is refreshed every 10 s and the list every 30 s with the pane open; nothing polls when
nothing is active, and remote runs never count as local operations.

The new read-only model tool `ms_deployment_status` (registered with the environment)
returns the latest run of a repository branch, or one run by uid, with its steps and
states, and with `logs: true` the last 80 log lines of the first failed step. It is
denied while no environment is selected. The worker reads
`/api/v1/deployment-history/`, `/api/v1/deployment-runs/{uid}/?include=workflow_run` and
its `/logs/` through the saved session and returns only what the pane draws; billing
and cost fields are never read into Claude, and a run that answers 404 is described
without asserting that it exists.
